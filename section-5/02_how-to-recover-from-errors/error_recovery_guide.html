How to Recover from Server Errors

Learn why calling reset() alone isn't enough for Server Component errors, and how combining it with router.refresh() & startTransition() creates flawless error recovery.

⚙️

1. Client Boundary State vs. Node.js Server Re-Execution

⚠️ Why reset() Alone Fails for Server Components

reset() only clears the client-side React Error Boundary state. Because page.js is a Server Component, calling reset() alone tries to re-render using the cached failed server response—causing the exact same error to trigger again!

🚀 The Solution: router.refresh() + reset()

router.refresh() clears Next.js client-side Data Cache and re-executes the Server Component (page.js) on the Node.js server. Wrapping both inside startTransition() ensures non-blocking, smooth UI recovery!

3. Code Anatomy: The Trio of Flawless Recovery

app/blogs/[blogID]/error.js Next.js App Router Standard
"use client"; import { useRouter } from "next/navigation"; // 1️⃣ For server route re-fetching import { startTransition } from "react"; // 2️⃣ For non-blocking state updates export default function Error({ error, reset }) { const router = useRouter(); return ( <div> <p>Something went wrong</p> <button onClick={() => { startTransition(() => { router.refresh(); // 👈 Re-executes page.js on Node.js Server reset(); // 👈 Clears Error Boundary UI state }); }} > Try Again </button> </div> ); }
