Handling Client-Side Exceptions & Strict Conventions

Understand how Next.js App Router handles client-side runtime errors and why strict file naming (error.js vs errors.js) determines whether React Error Boundaries are created.

⚙️

1. Next.js Strict Convention: error.js vs errors.js

❌ Starter Typo: errors.js (Unrecognized)

In starter code, the developer named the file errors.js (plural with an 's'). Next.js treats this as a regular helper file and DOES NOT create a React Error Boundary! Unhandled errors cause the page to crash or unmount completely.

✅ Final Fix: error.js (Recognized Convention)

Naming the file strictly error.js (singular) instructs Next.js compiler to automatically wrap the route segment inside a React <ErrorBoundary>. Client-side runtime exceptions are caught gracefully!

5. Poora Saar & Golden Master Rule (Hinglish)

💡 Client-Side Exceptions & Convention Ka Poora Saar:

Next.js App Router me file names ka Strict Convention hota hai! Jab aap file ka naam errors.js (plural with an 's') rakh dete ho, toh Next.js use ek normal utility file samajhta hai aur **React Error Boundary** create nahi karta!

Jaise hi aap naam error.js (singular) karte ho, Next.js ka compiler automatically route segment ko React <ErrorBoundary> me wrap kar deta hai. Ab chahe Server Error aaye ya Browser me Client-Side Exception (JS Error) phate, aapka fallback UI screen par smoothly render ho jayega!

🔥 3 Rules to Remember Forever:
  • 1. Strict Name 🎯 ➔ File ka naam ALWAYS error.js or error.jsx hona chahiye (NOT errors.js!).
  • 2. Client Boundary 🌐 ➔ error.js ke top par ALWAYS "use client" hona chahiye!
  • 3. Instant Client Catch ⚡ ➔ Client-Side Exceptions (Browser JS Errors) immediate Catch hote hain aur client boundary UI load ho jata hai.
