app/todos/route.js (Mongoose Implementation) GET & POST Endpoints 
import { connectDB } from "@/lib/connectDB";
import Todo from "@/models/todoModel";

// 🟢 READ: Fetch all todos from MongoDB
export async function GET() {
  await connectDB();
  const allTodos = await Todo.find();

  // Clean mapping to return virtual string id
  return Response.json(
    allTodos.map(({ id, text, completed }) => ({ id, text, completed }))
  );
}

// 🔵 CREATE: Add a new todo document in MongoDB
export async function POST(request) {
  await connectDB();

  const todo = await request.json();
  const { id, text, completed } = await Todo.create({ text: todo.text });

  return Response.json(
    { id, text, completed },
    { status: 201 }
  );
}
Mongoose Virtual `id` vs `_id`

MongoDB har document ko ek binary ObjectId assign karta hai (property name: _id).
Lekin Mongoose ek convenient Virtual Getter provide karta hai: doc.id jo doc._id.toString() return karta hai!
Isse hamara React frontend seamlessly todo.id use kar sakta hai bina kisi breaking change ke!

Always await connectDB() First

Har Route Handler function ke top par await connectDB(); lagana zaroori hai. Kyunki Next.js stateless serverless functions ki tarah act karta hai, yeh check karta hai ki database connection active hai ya nahi.
