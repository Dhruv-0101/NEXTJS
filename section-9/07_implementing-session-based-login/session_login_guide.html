Implementing Session-Based Login Architecture

Learn how industry-standard session management stores active session records in a MongoDB Session collection while providing instant server-side revocation capabilities.

⚙️

1. Stateful Session Architecture vs Direct Cookie ID

⚠️ Why Direct userId Cookie Is Limited

If a cookie directly stores userId, the server CANNOT force-logout a user or revoke stolen sessions! The cookie remains valid until its maxAge expires.

🚀 MongoDB Session Store Architecture

1. User logs in ➔ Server creates a Session document in MongoDB: { userId, createdAt }.
2. Server issues a signed cookie storing sessionId (not userId!).
3. On API requests, server verifies sessionId against MongoDB. Deleting the Session record instantly revokes access!

3. Code Breakdown: models/sessionModel.js & lib/auth.js

models/sessionModel.js MongoDB Session Schema
import mongoose, { Schema } from "mongoose"; const Session = mongoose.models.Session || mongoose.model("Session", { userId: { type: Schema.Types.ObjectId, required: true }, createdAt: { type: Date, default: Date.now, expires: 3600 * 24 * 7 // 👈 Auto TTL Index: MongoDB deletes after 7 days } }); export default Session;
lib/auth.js 2-Step Lookup: Cookie ➔ Session ➔ User
export async function getLoggedInUser() { const cookieStore = await cookies(); const cookie = cookieStore.get("userId")?.value; const sessionId = verifyCookie(cookie); if (!sessionId) return errorResponse; // Step 1: Look up Session in DB const session = await Session.findById(sessionId); if (!session) return errorResponse; // Revoked or Expired! // Step 2: Fetch User using session.userId const user = await User.findById(session.userId); return user; }

5. Poora Saar & Golden Master Rule (Hinglish)

💡 Session-Based Auth Ka Poora Saar:

Production Web Apps me cookie me direct userId rakhna aachi practice nahi hoti kyunki server par user ko Instant Logout karne ki taakat nahi rehti.

Isiliye hum **Session-Based Login** use karte hain:
1. User Login karta hai ➔ MongoDB me Session Document banta hai ({ _id: "sess_123", userId: "user_456" }).
2. Cookie me sessionId bhejte hain (Signed HMAC ke sath).
3. Request aane par server pehle DB me check karta hai: "Kya sess_123 active hai?" Agar haan, tabhi user authenticate hota hai! Agar server DB se session delete kar de ➔ User instant Logout ho jata hai!

🔥 Session Store Golden Pattern:
  • 1. Store sessionId in Cookie 🍪 ➔ Never store raw userId in client cookies.
  • 2. MongoDB TTL Index 🕒 ➔ Set expires: 3600 * 24 * 7 on Session schema for automatic DB cleanup.
  • 3. 2-Step Verification 🔍 ➔ Cookie ➔ Session Lookup ➔ User Lookup.
