Protecting Endpoints with Reusable Auth Function

Learn how to centralize authentication logic using a reusable getLoggedInUser() helper function across API endpoints to scope data specifically to the authenticated user.

⚙️

1. Reusable Auth Protection Architecture

🔒 Centralized getLoggedInUser() Helper

Instead of duplicating cookie parsing and MongoDB user validation in every single route handler, we abstract it into lib/auth.js.
If the cookie is missing or user invalid ➔ Returns pre-configured Response 401 Unauthorized!

🎯 Instanceof Early Exit Guard

Inside route handlers: const user = await getLoggedInUser();
if (user instanceof Response) return user; If unauthorized, the handler immediately returns the 401 Response! Otherwise, execution proceeds with valid user object.

import User from "@/models/userModel"; import { cookies } from "next/headers"; export async function getLoggedInUser() { const cookieStore = await cookies(); const errorResponse = Response.json( { error: "Please login" }, { status: 401 } ); const userId = cookieStore.get("userId")?.value; if (!userId) return errorResponse; const user = await User.findById(userId); if (!user) return errorResponse; return user; }

5. Poora Saar & Golden Master Rule (Hinglish)

💡 Reusable Auth Protection Ka Poora Saar:

Sabhi protected API routes (e.g. GET todos, POST todo, GET profile) me cookie check and DB user validation ka code bar-bar copy-paste karne ke bajaye ek central helper getLoggedInUser() banaya jata hai.

Ye helper do cheezon me se ek hi return karta hai:
1. Agar login nahi hai ➔ Pre-configured Response.json({ error: "Please login" }, { status: 401 }).
2. Agar login verified hai ➔ MongoDB user object.
Isiliye route handler me if (user instanceof Response) return user; likhte hi unauthorized requests instant block ho jaati hain!

🔥 DRY Protection Golden Pattern:
  • 1. Centralized Auth 🔒 ➔ Keep all cookie extraction & DB user checks in lib/auth.js.
  • 2. Instanceof Guard 🛡️ ➔ Use if (result instanceof Response) return result; at top of handlers.
  • 3. Scoped Data Queries 🎯 ➔ Always query DB with { userId: user.id } so users can ONLY access their own data!
