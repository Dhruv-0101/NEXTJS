1. Plain Cookie Vulnerability vs HMAC Signing Solution

❌ The Danger of Plain Cookies

If a cookie stores raw userId=123, an attacker can open Chrome DevTools and change it to userId=1 (Admin ID)!
The server cannot tell whether userId=1 was issued by the server or forged by the user!

✅ HMAC-SHA256 Signed Cookie Solution

Format: value.signature (e.g. 123.a7f9b...).
The server generates HMAC signature using a secret key (process.env.COOKIE_SECRET).
If a user alters 123 to 1, HMAC verification fails because the signature won't match!

3. Code Breakdown: lib/auth.js (Cryptographic Functions)

lib/auth.js HMAC Cookie Signing Engine
import { createHmac } from "crypto"; // 1️⃣ Generate HMAC Signature (value + secret -> signature): export function signCookie(cookie) { const signature = createHmac("sha256", process.env.COOKIE_SECRET) .update(cookie) .digest("hex"); return `${cookie}.${signature}`; // e.g. "userId.a7f9b..." } // 2️⃣ Verify Cookie Signature: export function verifyCookie(signedCookie) { const [cookie, cookieSignature] = signedCookie.split("."); const expectedSignature = signCookie(cookie).split(".")[1]; // 🛡️ Compare server-calculated HMAC vs incoming signature: if (expectedSignature === cookieSignature) { return cookie; // Signature valid! Returns original value } return false; // TAMPER DETECTED! Reject request. }

5. Poora Saar & Golden Master Rule (Hinglish)

💡 Signed Cookies Ka Poora Saar:

Plain cookie me rakhi kisi bhi value (e.g. userId=123) ko user DevTools khol kar change karke kisi aur ka account access kar sakta hai (Tamper Attack).

Isse bachne ke liye hum cookie ko Sign karte hain (signCookie()). Node.js crypto.createHmac("sha256", process.env.COOKIE_SECRET) secret key ka use karke ek digital stamp/signature banata hai: value.signature. Jab request vaapas aati hai, server verifyCookie() se signature re-calculate karta hai. Agar user ne 1 character bhi chheda ➔ Signatures mismatch honge aur request instant reject ho jayegi!

🔥 HMAC Cookie Signing Rules:
  • 1. Secret Environment Key 🔑 ➔ ALWAYS store COOKIE_SECRET in .env.local (NEVER commit to GitHub!).
  • 2. Format Standard 🏷️ ➔ Use value.signature format for signed cookie payload.
  • 3. Instant Rejection 🛑 ➔ If signature check fails in verifyCookie(), return 401 Unauthorized immediately!
