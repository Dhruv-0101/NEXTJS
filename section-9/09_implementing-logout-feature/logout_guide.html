Implementing Logout & Session Invalidation API

Understand production-grade logout architecture: destroying active database sessions on the server while clearing client HTTP-Only cookies.

⚙️

1. Dual-Cleanup Logout Architecture

1️⃣ Server-Side Invalidation

Extracts the sessionId from the request cookie and deletes the document from MongoDB: await Session.findByIdAndDelete(sessionId).
Ensures that even if someone copied the cookie string, it becomes permanently useless on the server!

2️⃣ Client Cookie Cleanup

Executes cookieStore.delete("sid").
Sends a Set-Cookie: sid=; Expires=Thu, 01 Jan 1970 00:00:00 GMT header to clear the cookie from the browser store.
Returns 204 No Content.

4. Quick Knowledge Check

Q1: Why is clearing the cookie alone not enough for a secure logout in Session-based auth?

A) Cookies cannot be cleared in Next.js.
B) Because if the Session document remains active in MongoDB, an attacker who intercepted the cookie can still use it!
C) Clearing cookies requires a browser restart.

5. Poora Saar & Golden Master Rule (Hinglish)

💡 Logout Feature Ka Poora Saar:

Production App me Logout ka matlab sirf client side se cookie delete karna NAHI hota! Complete logout Dual-Cleanup se hota hai.

1. **Server DB Cleanup**: MongoDB se `Session.findByIdAndDelete(sessionId)` run karte hain taaki server par session ka vajood hi khatam ho jaye.
2. **Client Cookie Cleanup**: `cookieStore.delete("sid")` se browser ki cookie clear karte hain.
Status Code: Response me body nahi hoti, isiliye `204 No Content` status bhejna industry standard hai!

🔥 Logout Golden Pattern:
  • 1. Delete Session in DB 🗑️ ➔ Destroy the session record on the server first.
  • 2. Delete Cookie in Browser 🍪 ➔ Call cookieStore.delete("sid").
  • 3. Return 204 No Content ⚡ ➔ Return new Response(null, { status: 204 }).
