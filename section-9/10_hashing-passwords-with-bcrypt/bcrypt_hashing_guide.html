1. Plaintext Vulnerability vs Bcrypt Hashing

❌ Plaintext Password Catastrophe

Storing password: "mypassword123" directly in MongoDB means a single database leak exposes all user passwords globally!
It also allows rogue admins/developers to read user credentials in cleartext.

✅ Bcrypt One-Way Salted Hashing

• bcrypt.hash(password, 10) ➔ Converts plaintext password into an irreversible, salted hash string (e.g. $2b$10$e8K...).
• bcrypt.compare(plaintext, hash) ➔ Cryptographically compares plaintext against the hash during login without ever decrypting it!

3. Code Breakdown: Registration & Login Handlers

app/api/register/route.js Hashing Password on Registration
import bcrypt from "bcrypt"; export async function POST(request) { const { name, email, password } = await request.json(); // 🔒 Hash plaintext password with 10 salt rounds: const hashedPassword = await bcrypt.hash(password, 10); const newUser = await User.create({ name, email, password: hashedPassword // 👈 Saved as "$2b$10$e8K..." in DB }); return Response.json(newUser, { status: 201 }); }
app/api/login/route.js Comparing Password on Login
import bcrypt from "bcrypt"; export async function POST(request) { const { email, password } = await request.json(); const user = await User.findOne({ email }); // 🛡️ Compare incoming plaintext password against DB hash: const isPasswordValid = await bcrypt.compare(password, user.password); if (!user || !isPasswordValid) { return Response.json({ error: "Invalid Credentials!" }, { status: 400 }); } // Success: Proceed with Session creation }

4. Quick Knowledge Check

Q1: Can a Bcrypt hash string be decrypted back into the original plaintext password?

A) Yes, using bcrypt.decrypt().
B) NO! Bcrypt is a ONE-WAY cryptographic hashing algorithm. Hashes cannot be reversed.
C) Yes, if you possess the secret env key.

5. Poora Saar & Golden Master Rule (Hinglish)

💡 Password Hashing Ka Poora Saar:

Database me plain text password rakhna Software Engineering me sabse bada paap (Fatal Vulnerability) hai!

Bcrypt two-stage workflow par kaam karta hai:
1. **Registration**: await bcrypt.hash(password, 10) run karke password ko $2b$10$e8K... me transform karke DB me save karte hain. (Yeh One-Way hai — isko reverse/decrypt KABHI nahi kiya ja sakta!).
2. **Login**: await bcrypt.compare(incomingPassword, dbHashedPassword) chalate hain. Bcrypt internally same salt apply karke match verify karta hai aur boolean `true/false` return karta hai!

🔥 Password Security Golden Rules:
  • 1. Always Hash on Register 🔒 ➔ Never execute User.create() with raw password text.
  • 2. Salt Rounds = 10 ⚡ ➔ Use 10 salt rounds for optimal CPU performance vs security trade-off.
  • 3. Always Use bcrypt.compare 🛡️ ➔ Never use string comparison (===) for hashed passwords.
