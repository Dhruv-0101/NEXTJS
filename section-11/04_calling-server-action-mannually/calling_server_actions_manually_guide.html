Calling Server Actions Manually & Client Validation

Understand how wrapping Server Actions inside custom client event handlers allows executing client-side form validation and sending custom JavaScript objects.

⚙️

1. Direct Binding vs. Manual Wrapper Handler

⚡ Direct Binding (<form action={formAction}>)

Directly submits raw FormData to the server without any client-side validation check.
Sends network request immediately even if fields are invalid or empty!

🛡️ Manual Wrapper (<form action={handleFormAction}>)

Intercepts submission in handleFormAction.
Checks rules (e.g. name ≥ 3 chars, password ≥ 8 chars).
If invalid ➔ Stops execution & sets error state!
If valid ➔ Manually invokes formAction(newUser)!

🔄

2. How Custom Objects Change the Server Action Signature

When you manually call formAction(newUser) passing a custom object { name, email, password } instead of raw FormData, the Server Action receives that custom object as its second argument!

// app/actions/userAction.js
"use server";

export async function registerUser(_, formData) {
  // formData is now the custom JS object: { name: "...", email: "...", password: "..." }
  console.log(formData.email); // 👈 Direct property access instead of .get()!
  return { message: `${formData.email} registered` };
}

💡 Calling Server Actions Manually Ka Poora Saar:

Isse bachne ke liye hum ek custom wrapper handler `handleFormAction` banate hain:
1. Client Form par `` bind karte hain.
2. `handleFormAction` pehle client-side JS rules check karta hai (Name length, Email format, Password length).
3. Agar koi error mila ➔ Function wahin `return` karke Network Request ko STOPS (Block) kar deta hai!
4. Agar saare checks pass ho gaye ➔ Tab manually formAction(newUser) ko custom object ke saath invoke karta hai!

🔥 Manual Action Golden Pattern:
  • 1. Client Validation First 🛡️ ➔ Validate form fields before triggering `formAction()`. Saves unnecessary server resources.
  • 2. Custom Payload Support 📦 ➔ Calling formAction(customObj) passes custom JS objects directly to the Server Action.
  • 3. Direct Property Access 🔑 ➔ In Server Action, access fields directly via `formData.email` instead of `formData.get("email")`.
