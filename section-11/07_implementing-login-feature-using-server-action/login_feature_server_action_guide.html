2. DRY Architecture: Zod Schema Ko extend() Karna

Code duplication band: Login schema ko hi extend karke Register schema banaya!

Pehle humne dekha ki Login aur Register dono me email aur password ke validation rules (regex, error messages) 100% same hain. Agar dono alag likhein toh code duplicate hoga.

Zod ka super-clean tareeka: Pehele loginSchema banao, aur phir use extend karke registerSchema bana lo!

lib/schema/userSchema.js DRY Schema Extension
import { z } from "zod/v4"; // 1. Base Login Schema (Email + Password) export const loginSchema = z.object({ email: z.email("Please enter a valid email"), password: z.string().regex( /^(?=.*[a-z])(?=.*[A-Z])(?=.*\d).{8,}$/, "Enter at least 8 characters, with uppercase, lowercase, and a number." ), }); // 2. Register Schema extends Login Schema + Adds 'name' export const registerSchema = loginSchema.extend({ name: z .string() .min(3, "Name should be at least 3 characters") .max(100, "Name should be at max 100 characters"), });

4. Security Master Rule: Hacker Ko Hint Mat Do! (User Enumeration Defense)

Video me instructor ne ek bahut zaroori security concept live demo karke dikhaya:
Agar user ka email database me nahi mila ➔ toh kya hume "Email does not exist" bolna chahiye? Aur agar password galat hai ➔ toh kya "Incorrect password" bolna chahiye?

❌ "Email Does Not Exist" Kehne Ka Khatra:

Agar aap alag-alag error doge, toh koi bhi hacker hazaron email addresses daal kar check kar lega ki kaunsa email aapke platform par registered hai aur kaunsa nahi (isse User Enumeration Attack kehte hain!).

✅ The Production Security Golden Rule:

Chahe email galat ho ya password galat ho — dono cases me hamesha same error bhejo: "Invalid credentials" aur use password field ke neeche display karo! Isse hacker ko kabhi pata nahi chalega ki konsi cheez galat thi!

7. Client Component vs Server Action (Complete Implementation)

app/login/page.js vs app/actions/userAction.js (loginUser)

🌐 app/login/page.js ("use client") Client Page
"use client"; import { useActionState, useEffect, useState } from "react"; import { useRouter } from "next/navigation"; import { loginUser } from "../actions/userAction"; import { loginSchema } from "@/lib/schema/userSchema"; import { z } from "zod/v4"; export default function LoginPage() { const router = useRouter(); const [state, formAction, isPending] = useActionState(loginUser, {}); const [email, setEmail] = useState("procodrr@gmail.com"); const [password, setPassword] = useState("1234ABcd"); const [errors, setErrors] = useState({}); useEffect(() => { if (state.success) { router.push("/"); // 👈 Redirect to Home/Dashboard! } else { setErrors(state.errors); } }, [state]); const handleFormAction = async () => { const { success, data, error } = loginSchema.safeParse({ email, password }); if (!success) { return setErrors(z.flattenError(error).fieldErrors); } setErrors({}); formAction(data); }; return ( <form action={handleFormAction} noValidate> ... </form> ); }
⚙️ app/actions/userAction.js (loginUser) Server Action
"use server"; import bcrypt from "bcrypt"; import { connectDB } from "@/lib/connectDB"; import User from "@/models/userModel"; import Session from "@/models/sessionModel"; import { signCookie } from "@/lib/auth"; import { cookies } from "next/headers"; export async function loginUser(_, formData) { const { success, data, error } = loginSchema.safeParse(formData); if (!success) { return { success: false, errors: z.flattenError(error).fieldErrors }; } await connectDB(); const cookieStore = await cookies(); try { const { email, password } = data; const user = await User.findOne({ email }); if (!user) { return { errors: { password: "Invalid credentials" } }; } const isMatch = await bcrypt.compare(password, user.password); if (!isMatch) { return { errors: { password: "Invalid credentials" } }; } const session = await Session.create({ userId: user._id }); cookieStore.set("sid", signCookie(session.id), { httpOnly: true, maxAge: 60 * 60 * 24, }); return { success: true, message: "User logged in successfully" }; } catch (err) { return { errors: { email: "Something went wrong." } }; } }

8. Quick Quiz: Apne Concepts Test Karo

Sahi option choose karo

Sawaal 1: User login fail hone par "Email does not exist" ke bajaye "Invalid credentials" kyu return karte hain?

User Enumeration attack rokne ke liye, taaki hacker pata na laga sake ki kaunsa email registered hai.
Kyunki Zod me "Email does not exist" likhna mana hai.

Sawaal 2: Next.js Server Actions me session cookies kaise set ki jaati hain?

res.setHeader('Set-Cookie', ...) likh kar.
next/headers se `cookies()` store import karke direct `cookieStore.set('sid', ...)` chala kar!

9. Poora Saar (Golden Key Takeaways)

Production authentication ke 5 golden rules

  • DRY Schema Reusability: loginSchema.extend({ name: ... }) use karke register schema banao taaki validation rules baar-baar na likhne padein.
  • Anti-Enumeration Security: Chahe user na mile ya password wrong ho, error hamesha "Invalid credentials" hi bhejo.
  • Server Action Direct Cookies: const cookieStore = await cookies() se Server Action ke andar direct secure session cookie set ki ja sakti hai.
  • Redirect Destination: Register success par /login par bhejo, aur Login success par / (Home/Dashboard) par bhejo.
  • Zero Route Handlers Needed: Ab hamara Register aur Login dono bina kisi REST API endpoint ke 100% Server Actions se chal rahe hain!
