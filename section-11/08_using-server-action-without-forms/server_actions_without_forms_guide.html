Using Server Actions Without Forms

Sabse bada myth busted! Server Action chalane ke liye <form> tag ki koi zaroorat nahi hoti! Seekhein kaise kisi bhi normal button ke onClick event se server action call hota hai, arbitrary data pass kiya jaata hai, MongoDB se Session delete karke cookie destroy hoti hai, aur Todo CRUD mutations kaise perform hote hain!

💥

1. Sabse Bada Myth: "Kya Server Actions Sirf Forms Ke Sath Hi Chalte Hain?"

Forms vs Direct Event-Driven Invocations (onClick, useEffect)

👨‍🏫 Instructor Ki Zubani:

"Is video me hum dekhenge ki Server Actions ko bina form ke kaise use karte hain. Hamare to-do app me jo Logout button hai, uske charo taraf koi form nahi hai! Ab tak Logout ka logic Route Handler (fetch API) se chal raha tha. Ab hum direct onClick handler se Server Action call karke user ko logout karenge!"

📋 Form-Driven Invocations (<form action={...}>)

Inputs, FormData, aur progressive enhancement ke liye best hota hai. Usually Register aur Login jaise complex forms me use hota hai.

⚡ Direct Event-Driven Invocations (onClick)

Koi form tag nahi chahiye! Kisi bhi button ke onClick, toggle switch, ya useEffect me normal async function ki tarah await logoutUser() call kar sakte hain!

🚪

2. Logout Feature: Server Action & Session Cleanup

Pehle API route se Status 204 aata tha — ab Server Action se direct { success: true }

Logout karne ke liye hume client se koi data bhejne ki zaroorat nahi hoti! Kyunki browser request ke sath signed sid cookie automatically server par aati hai!

app/actions/userActions.js (logoutUser) Server Action
"use server"; import { cookies } from "next/headers"; import Session from "@/models/sessionModel"; import { getUserSessionId } from "@/lib/auth"; export async function logoutUser() { const cookieStore = await cookies(); const sessionId = await getUserSessionId(); // 1. MongoDB se session document delete karo await Session.findByIdAndDelete(sessionId); // 2. Browser ki cookie destroy karo cookieStore.delete("sid"); // 3. Return clean plain object return { success: true }; }
app/page.js (handleLogout) Direct onClick Handler
"use client"; import { useRouter } from "next/navigation"; import { logoutUser } from "./actions/userActions"; export default function Home() { const router = useRouter(); const handleLogout = async () => { // Direct function call! No fetch, no headers! const response = await logoutUser(); if (response.success) { return router.push("/login"); } }; return ( <button onClick={handleLogout}> Logout </button> ); }

3. Passing Arbitrary Arguments: FormData Ki Koi Zaroorat Nahi!

Instructor ne logoutUser({ name: "anurag" }) pass karke dikhaya

Jab hum form ke bina Server Action call karte hain, toh hum function me jo chahein wo arguments bhej sakte hain (numbers, strings, objects, IDs)!

// Client Call:
const res = await logoutUser({ name: "anurag", reason: "user_clicked" });

// Server Action:
export async function logoutUser(payload) {
  console.log(payload); // ➔ { name: "anurag", reason: "user_clicked" }
}

Next.js is payload ko **React Flight Protocol** ke through serialize karke server action ko direct deliver kar deta hai. Parameter ka naam `formData` rakhne ki koi pabandi nahi hai!

4. Master Concept: Server Actions Ka Asli Kaam Hai "MUTATIONS"

Instructor ne ek bahut important architectural principle explain kiya:
"Server Actions ka main purpose data MUTATIONS karna hai — yaani Create, Update, aur Delete!"

➕ Create Mutation

Naya todo create karna:
await createTodo({ text })

✏️ Update Mutation

Checkbox toggle ya edit karna:
await toggleTodo(id, completed)

🗑️ Delete Mutation

Todo ya session delete karna:
await deleteTodo(id)

Data Read (GET) karne ke liye kya use karein? Data read karne ke liye Next.js me **React Server Components (RSC)** recommended hote hain, jahan component direct database query chala kar HTML render karta hai!
