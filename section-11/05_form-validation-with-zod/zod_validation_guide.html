2. Centralized Schema (lib/schema/userSchema.js) & Regex Breakdown

Single Source of Truth jo Client aur Server dono jagah share hoga

Hum lib/schema/userSchema.js me ek schema banate hain jisme custom human-readable error messages define karte hain:

lib/schema/userSchema.js Zod v4 Schema
import { z } from "zod/v4"; export const registerSchema = z.object({ name: z .string() .min(3, "Name should be at least 3 characters") .max(100, "Name should be at max 100 characters"), email: z.email("Please enter a valid email"), password: z .string() .regex( /^(?=.*[a-z])(?=.*[A-Z])(?=.*\d).{8,}$/, "Enter at least 8 characters, with uppercase, lowercase, and a number." ), });

🔍 Password Regex Ka Postmortem:

  • (?=.*[a-z]) ➔ Kam se kam 1 lowercase character (a-z) hona compulsory hai.
  • (?=.*[A-Z]) ➔ Kam se kam 1 uppercase capital character (A-Z) hona compulsory hai.
  • (?=.*\d) ➔ Kam se kam 1 number digit (0-9) hona compulsory hai.
  • .{8,} ➔ Password ki total length minimum 8 characters honi chahiye.

3. safeParse Ka Jadoo: Extra Fields Ka Gayab Hona (Auto-Sanitization)

Hacker agar extra fields inject kare toh Zod unka kya karta hai?

Jab hum registerSchema.safeParse(newUser) call karte hain, toh ye 3 properties return karta hai:

const { success, data, error } = registerSchema.safeParse(newUser);

🧪 Instructor Ka Live Experiment (The "age" Property):

Instructor ne video me jan-bujh kar object me ek extra property pass ki: { name: "ProCodrr", email: "...", password: "...", age: 25 }.

Lekin jab ye Zod schema se pass hua, toh result.data me se `age` automatically gayab ho gayi!
Kyunki schema me sirf 3 properties defined thin: name, email, password.

Security Superpower: Zod un-wanted ya malicious extra fields (jaise isAdmin: true) ko automatically strip kar deta hai! Isliye hum form action me formAction(data) bhejte hain, un-sanitized raw data nahi!

4. Error Formatting: z.flattenError(error).fieldErrors

Zod v4 me complex error issues ko simple key-value format me convert karna

By default, Zod ka error.issues ek lamba aur complex array of objects hota hai jisme path, code, message hote hain. Isse direct UI par render karna mushkil tha.

Zod v4 me naya function aaya hai: z.flattenError(error).fieldErrors jo errors ko simple key-value format me convert kar deta hai:

Flattened fieldErrors Object Clean Key-Value Mapping
{ name: ["Name should be at least 3 characters"], email: ["Please enter a valid email"], password: ["Enter at least 8 characters, with uppercase, lowercase, and a number."] }

React me kyunki arrays ko direct JSX me render kiya ja sakta hai (<p>{errors?.email}</p>), yeh direct bina kisi loop ke screen par display ho jaata hai!

6. Dono Taraf Validation Kyu Lagana Zaroori Hai? (Defense in Depth)

Instructor ne ek bahut profound baat boli: "Client-side code is UNSAFE code."

⚡ Client-Side Validation (The Speed Shield)

Kyun Lagate Hain? Fast User Experience ke liye! User ko 0ms me turant pata chal jaata hai ki email galat hai ya password chhota hai. Network request nahi jaati, server load bachta hai.

Weakness: Browser me chal raha JS code user inspect element karke modify kar sakta hai, ya direct Postman / cURL se request bhej sakta hai!

🔒 Server-Side Validation (The Security Vault)

Kyun Lagate Hain? Rock-solid Security ke liye! Hacker chahe client validation ko bypass kar le, server par same Zod schema dobara check karega aur malicious data ko reject kar dega (NoSQL / SQL Injection prevention).

Weakness: Network round-trip lagta hai (slow feedback if network is slow).

👉 Conclusion: Client gives SPEED, Server gives SECURITY. Dono milkar bante hain Complete Application!

💻

7. Client Component vs Server Action (Complete Implementation)

Notice how both share the exact same registerSchema

app/register/page.js ("use client") Client Handler
"use client"; import { useActionState, useEffect, useState } from "react"; import { registerSchema } from "@/lib/schema/userSchema"; import { z } from "zod/v4"; export default function RegisterPage() { const [state, formAction, isPending] = useActionState(registerUser, {}); const [errors, setErrors] = useState({}); // Sync server errors to local error state useEffect(() => { setErrors(state.errors); }, [state.errors]); const handleFormAction = async (formData) => { const newUser = { name: formData.get("name"), email: formData.get("email"), password: formData.get("password"), }; const { success, data, error } = registerSchema.safeParse(newUser); if (!success) { return setErrors(z.flattenError(error).fieldErrors); } setErrors({}); formAction(data); // 👈 Send clean sanitized data! }; return ( <form action={handleFormAction} noValidate> <input name="name" ... /> <p>{errors?.name}</p> ... </form> ); }
app/actions/userAction.js ("use server") Server Action
"use server"; import { registerSchema } from "@/lib/schema/userSchema"; import { z } from "zod/v4"; export async function registerUser(_, formData) { // Validate on Server again (Security Defense) const { success, data, error } = registerSchema.safeParse(formData); if (!success) { // Return errors to client return { errors: z.flattenError(error).fieldErrors }; } // Data is 100% sanitized and validated! return { message: `${data.email} registered`, data }; }

8. Quick Quiz: Apne Concepts Test Karo

Sahi option choose karo

Sawaal 1: Agar client se kisi hacker ne `{ name: 'ProCodrr', email: '...', password: '...', isAdmin: true }` bhej diya, toh Zod safeParse ke baad `result.data` me kya hoga?

Zod error throw karega kyunki extra field allow nahi hoti.
Zod us `isAdmin` property ko automatically strip (gayab) kar dega, aur sirf schema fields bachengi!

Sawaal 2: Client validation hone ke bawajood Server-side validation kyu zaroori hai?

Kyunki client code unsafe hota hai; hacker DevTools ya Postman se client validation bypass karke server par attack kar sakta hai.
Kyunki bina server validation ke Next.js build fail ho jaata hai.

9. Poora Saar (Golden Key Takeaways)

Production apps ke liye 5 zaroori baatein

  • Single Source of Truth: userSchema.js me ek baar schema banao aur use Client component aur Server action dono jagah import karo.
  • Auto-Sanitization: registerSchema.safeParse(...) extra fields ko discard kar deta hai, isliye hamesha formAction(data) pass karo.
  • z.flattenError(error).fieldErrors: Zod v4 me nested errors ko clean key-value format me convert karta hai jise React direct UI me render kar sakta hai.
  • Syncing with useEffect: Server-side errors ko client state me reflect karne ke liye useEffect(() => setErrors(state.errors), [state.errors]) ka use karo.
  • Defense in Depth: Client validation = 0ms fast feedback (UX). Server validation = Rock-solid database protection (Security).
