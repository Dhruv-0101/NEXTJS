Form Validation with Zod & Server Actions

Master production form validation using Zod schemas: share a single validation contract between client pre-flight checks and server-side action guards.

⚙️

1. Dual-Layer Validation Architecture (Defense in Depth)

🌐 Layer 1: Client Pre-Flight Validation

Executes registerSchema.safeParse(newUser) inside handleFormAction.
If invalid ➔ Extracts z.flattenError(error).fieldErrors, updates React state, and stops network execution on client!

⚙️ Layer 2: Server Action Validation Guard

Never trust client inputs! Server Action re-executes registerSchema.safeParse(formData).
If an attacker bypasses client JS via Postman or Curl, the Server Action rejects invalid data and returns { errors }.

📜

2. Zod Schema Definition & `flattenError` Formatting

// lib/schema/userSchema.js
export const registerSchema = z.object({
  name: z.string().min(3, "Name should be at least 3 characters").max(100),
  email: z.email("Please enter a valid email"),
  password: z.string().regex(
    /^(?=.*[a-z])(?=.*[A-Z])(?=.*\d).{8,}$/,
    "Enter at least 8 characters, with uppercase, lowercase, and a number."
  )
});
✨ z.flattenError(error).fieldErrors Format:

Converts raw Zod error syntax trees into simple key-value objects matching form field names:
{ name: ["Min 3 chars"], password: ["Enter at least 8 characters, with uppercase, lowercase, and a number."] }

4. Side-by-Side Code Breakdown: Client Page vs. Server Action

app/register/page.js (Client Pre-Flight)
"use client"; import { registerSchema } from "@/lib/schema/userSchema"; import { z } from "zod"; const handleFormAction = async (formData) => { const newUser = { name: formData.get("name"), email: formData.get("email"), password: formData.get("password"), }; // 1️⃣ Client Pre-flight Zod Check: const { success, data, error } = registerSchema.safeParse(newUser); if (!success) { return setErrors(z.flattenError(error).fieldErrors); } setErrors({}); return formAction(data); };
app/actions/userAction.js (Server Enforcement)
"use server"; import { registerSchema } from "@/lib/schema/userSchema"; import { z } from "zod"; export async function registerUser(_, formData) { // ⚙️ 2️⃣ Server Enforcement Zod Check: const { success, data, error } = registerSchema.safeParse(formData); if (!success) { return { errors: z.flattenError(error).fieldErrors }; } return { message: `${formData.email} registered`, data }; }

6. Poora Saar & Golden Master Rule (Hinglish)

💡 Form Validation With Zod Ka Poora Saar:

Manual `if` conditions (jaise `if (email.indexOf("@") === -1)`) se form validation karna amateur tareeka hai. Production apps me Zod Schema use hota hai.

Zod validation Dual-Layer Defense par kaam karta hai:
1. **Single Source of Truth (`userSchema.js`)**: Ek central file me `registerSchema` define karte hain (e.g. `z.email()`, `z.string().min(3)`, `z.string().regex(...)`).
2. **Layer 1 (Client Pre-Flight)**: Form submit hote hi `registerSchema.safeParse(newUser)` chalta hai. Agar validation fail huyi ➔ `z.flattenError(error).fieldErrors` se errors nikaal kar screen par dikha dete hain aur **Server Call KO WAHIN BLOCK kar dete hain**!
3. **Layer 2 (Server Enforcement)**: Server Action ke andar `registerSchema.safeParse(formData)` phirse run karta hai. Isse agar koi hacker Postman/Curl se direct API hit kare, tab bhi Server use block kar deta hai!

🔥 Zod Validation Golden Pattern:
  • 1. Single Shared Schema 📜 ➔ Define Zod schemas in lib/schema/ and import on both client page and server action.
  • 2. safeParse Everywhere 🛡️ ➔ Always use safeParse() (not parse()) to handle errors gracefully without app crashes.
  • 3. flattenError Parsing 🏷️ ➔ Use z.flattenError(error).fieldErrors to get clean `{ fieldName: ["Error msg"] }` objects for form UI.
