2. useActionState Kya Return Karta Hai? (3 Values Ka Array)

Instructor ne console.log(a) karke dekha toh 3 cheezein mili

Jab hum useActionState(registerUser, {}) call karte hain, toh ye hume ek Array (Tuple) return karta hai jisme 3 powerful weapons hote hain:

const [state, formAction, isPending] = useActionState(registerUser, {});
Value 0
📦 state

Yeh wo variable hai jisme Server Action ka return value aakar baithta hai! Jab tak submit nahi hua, tab tak yeh initialState (jo humne second argument me pass kiya) rehta hai. Submit hone ke baad server ka return object isme aa jaata hai.

Value 1
⚡ formAction

Yeh ek wrapped function hai jo useActionState hume deta hai. Ab hum original registerUser ko form par nahi lagayenge, balki is formAction ko <form action={formAction}> par lagayenge!

Value 2
⏳ isPending

Ek Boolean (true / false). Jaise hi user ne submit button dabaya, jab tak server se response wapas nahi aa jaata, tab tak yeh true rehta hai! Iska use button disable karne aur loader dikhane ke liye hota hai.

💥

3. Bada Trap (Aha Moment #1): "Cannot read properties of undefined (reading 'get')"

useActionState lagate hi Server par error kyu aaya aur arguments kaise badle?

🚨 Server Terminal Par Aaya Fatal Error:
TypeError: Cannot read properties of undefined (reading 'get') at registerUser (app/actions/userAction.js:5:18)

🧠 Dhyan Se Samjho: Arguments Ka Khel Badal Gaya!

Jab hum Server Action ko seedha <form action={registerUser}> par lagate the, toh function ko sirf 1 argument milta tha: formData.

Lekin jab aap Server Action ko useActionState ke through pass karte ho, toh React aapke function ko DO (2) arguments bhejta hai:

❌ Pehle Direct Form Action Tha:
export async function registerUser(formData) { // Sirf 1 argument milta tha: formData const name = formData.get("name"); }
✅ useActionState Ke Sath Signature:
export async function registerUser(previousData, formData) { // Argument 1 = previousData (State of previous cycle) // Argument 2 = formData (Asli form inputs!) const name = formData.get("name"); }

previousData kya hota hai?
Pehli baar submit karne par previousData wahi hota hai jo aapne initial state diya tha (jaise `{}` ya `undefined`). Lekin jab user dobara form submit karta hai, toh server action ne pichli cycle me jo return kiya tha (jaise `{ message: "procodrr@gmail.com registered" }`), wo previousData bankar server ke paas wapas pahunchta hai!

💡

4. Trap #2: Cannot read properties of undefined (reading 'message')

Initial State pass karna kyu mandatory ban jaata hai?

Instructor ne jab UI par message show karne ke liye likha: <p>{state.message}</p>, toh page crash ho gaya!
Kyun? Kyunki by default state ki initial value undefined hoti hai. Aur JavaScript me undefined.message padhne jaoge toh browser fat jayega!

✅ The Clean Fix: Initial Value Pass Karo

const [state, formAction, isPending] = useActionState(registerUser, {});

Ab page load hote hi state ek empty object {} hoga. Aur {}.message JavaScript me error nahi deta, balki safely undefined return karta hai, jisse UI crash hone se bach jaata hai!

6. Sabse Bada Architectural Revelation: Server Actions Me Hamesha 200 OK Kyu Aata Hai?

Purane REST API routes me jab user galat password daalta tha ya account nahi banta tha, toh hum backend se HTTP 400 ya 500 bhejte the: res.status(400).json({ error: "Failed" }).

🔥 Server Actions Ka Golden Rule:

Server Actions REST API ki tarah behave nahi karte! Server Action hamesha ek HTTP POST request hota hai aur uska HTTP Status code hamesha 200 OK hi hota hai — chahe database fail ho, ya user validation fail ho!

Agar error aata hai, toh hum server se payload ke andar data bhejte hain jaise:
return { error: "procodrr@gmail.com not registered" } ya return { myError: "Something went wrong" }.

Aap property ka naam kuch bhi rakh sakte ho (error, myError, status). Phir UI par aap state.error ya state.message check karke red/green text dikha sakte ho.

10. Poora Saar (Golden Key Takeaways)

Aapki jeb me rakhne layak 6 sabse zaroori baatein

  • useActionState Import: Yeh React 19 ka hook hai, isko react package se import kiya jaata hai.
  • Tuple Destructuring: const [state, formAction, isPending] = useActionState(action, initialState).
  • Function Signature Trap: useActionState lagate hi Server Action ka pehla parameter previousData ban jaata hai aur doosra formData!
  • Initial State Zaroori Hai: useActionState(registerUser, {}) me empty object {} pass karne se state.message padhne par page crash nahi hota.
  • isPending UX: Form submit hone par isPending = true hota hai, jisse button disable aur opacity low ki ja sakti hai duplicate submission rokne ke liye.
  • HTTP 200 OK Everywhere: Server actions me traditional status codes (400/500) nahi aate; success aur error dono 200 OK me custom JSON objects ke roop me aate hain.
