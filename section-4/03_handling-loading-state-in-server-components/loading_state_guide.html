03. Handling Loading State in Server Components

How Next.js uses loading.js to stream instant Shimmer skeletons while waiting for slow server-side API responses.

The Architecture: page.js + loading.js

Next.js has a special file convention: if you put a loading.js file next to your page.js, Next.js automatically wraps that page inside a React Suspense Boundary.

📄 app/todos/loading.js

export default function Loading() { return ( <> <h1>Todos</h1> <div className="todos-container"> {Array.from({ length: 5 }).map((_, index) => ( <li key={index} className="shimmer"> <div className="shimmer-checkbox"></div> <div className="shimmer-text"></div> </li> ))} </div> </> ); }

📄 app/todos/page.js (Slow 5s Fetch)

const Todos = async () => { // Simulates a 5 second slow server delay! const slowResponse = await fetch( "https://procodrr.vercel.app/?sleep=5000" ); const data = await slowResponse.json(); const response = await fetch( "https://jsonplaceholder.typicode.com/todos?_limit=5" ); const todos = await response.json(); return ( <> <h1>Todos</h1> <div className="todos-container"> {todos.map(({ id, title, completed }) => ( <div className="todo-item" key={id}> <input type="checkbox" checked={completed} readOnly /> <p>{title}</p> </div> ))} </div> </> ); };

Behind The Scenes: What Next.js Does Under The Hood

Jab aap ek folder ke andar loading.js banate ho, toh Next.js compile time par aapke layout.js aur page.js ke beech me yeh code generate karta hai:

// Next.js Internal Code Representation <Layout> <Suspense fallback={<Loading />}> <TodosPage /> </Suspense> </Layout>

💡 Nateeja: User ko 5 second tak safed (blank) screen nahi dekhni padti! Browser ko 0ms par hi Shimmer animation mil jata hai, aur jaise hi server pe data resolve hota hai, Next.js HTML stream bhej kar skeleton ko real todos se replace kar deta hai.
