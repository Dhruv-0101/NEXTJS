05. Parallel Data Fetching in Next.js

How sequential await creates an accidental 5.5s waterfall, and how Promise.all() runs all requests simultaneously to cut load time to 3.0s!

Starter (Sequential Waterfall) vs Final (Promise.all)

Starter: Waterfall Fetching

Total: ~5.5s

Each await blocks the execution until it finishes before starting the next one!

// 1. Wait 0.5s for Todos const res1 = await fetch(".../todos"); const todos = await res1.json(); // 2. THEN wait 2.0s for Slow2s const res2 = await fetch("...?sleep=2000"); const data2s = await res2.json(); // 3. THEN wait 3.0s for Slow3s const res3 = await fetch("...?sleep=3000"); const data3s = await res3.json(); // Total Time = 0.5s + 2s + 3s = 5.5s! ❌

Final: Parallel Fetching

Total: ~3.0s

All 3 requests fire simultaneously at 0s! The total time is just the single longest request!

const urls = [ "https://jsonplaceholder.typicode.com/todos?_limit=5", "https://procodrr.vercel.app/?sleep=2000", "https://procodrr.vercel.app/?sleep=3000", ]; // All 3 fetches start in parallel at 0ms! const [todos, data2s, data3s] = await Promise.all( urls.map((url) => fetchData(url)) ); // Total Time = max(0.5s, 2s, 3s) = 3.0s! 🚀

Promise.all vs <Suspense>: Kab Kaunsa Use Karein?

Pattern Execution When To Choose?
Promise.all() Single Component me sab parallel fetch hota hai, aur poora component ek sath render hota hai. Jab saara data ek-dusre par dependent ho ya ek hi table/graph me dikhana ho.
Component <Suspense> Alag-alag components parallel fetch karte hain aur jaise-jaise ready hote hain, stream hokar UI render karte hain. Jab page ke alag sections hon (e.g. Comments 15s me aayenge, Profile 1s me turant dikhana hai).
