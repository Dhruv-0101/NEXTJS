04. Using Suspense to Handle Loading State

Why route-level loading.js is not enough, and how wrapping individual async components in <Suspense> streams fast components without waiting for slow ones!

The Core Problem: All-or-Nothing with loading.js

Ek Slow Component Poore Page Ko Block Kar Deta Hai!

Agar aapke page me 3 components hain:
• SlowComponent2s (2 seconds)
• SlowComponent3s (3 seconds)
• TodoItems (5 seconds)

Agar aap sirf loading.js use karte ho, toh Next.js poore page ko ek sath rok leta hai. User ko 5 full seconds tak skeleton dikhta rahega, bhale hi 2s wala component 2 second me ready ho chuka tha!

✅ The Solution: Granular <Suspense> Boundaries

import SlowComponent2s from "@/components/SlowComponent2s"; import SlowComponent3s from "@/components/SlowComponent3s"; import TodoItems from "@/components/TodoItems"; import { Suspense } from "react"; const Todos = async () => { return ( <> <h1>Todos</h1> {/* Component 1 (5s Delay) */} <Suspense fallback={<ShimmerSkeleton />}> <TodoItems /> </Suspense> {/* Component 2 (2s Delay) - Loads at 2s independently! */} <Suspense fallback={<div>Loading data 1...</div>}> <SlowComponent2s /> </Suspense> {/* Component 3 (3s Delay) - Loads at 3s independently! */} <Suspense fallback={<div>Loading data 2...</div>}> <SlowComponent3s /> </Suspense> </> ); }; export default Todos;

Project Notes: Exact Execution Timeline

Time 0s: Sabka fetch ek sath start hota hai (Parallel initiation) 🚀
• Slow2s: waiting (2s)
• Slow3s: waiting (3s)
• TodoItems: waiting (5s)
Time 2s:
• Slow2s: ✅ DONE → Instant HTML chunk streamed & UI updated!
• Slow3s: waiting (fallback active)
• TodoItems: waiting (fallback active)
Time 3s:
• Slow3s: ✅ DONE → Second HTML chunk streamed & UI updated!
• TodoItems: waiting (fallback active)
Time 5s:
• TodoItems: ✅ DONE → Final chunk streamed & Todos rendered!
