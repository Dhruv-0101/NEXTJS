Defining export function GET()

The standard convention for handling HTTP GET requests in Next.js App Router

Next.js App Router mein jab client se koi GET request /todos par aati hai, Next.js app/todos/route.js ke exported GET() function ko execute karta hai.

app/todos/route.js Next.js 15 Implementation 
import todosData from "../../todos";

// 🟢 Approach 1: Modern Web Standard (Recommended)
export function GET() {
  return Response.json(todosData);
}

Response.json(todosData)

Shorthand method added to the Fetch API standard. Yeh automatically JSON.stringify() call karta hai aur response header mein Content-Type: application/json set kar deta hai. 99% cases mein yahi use hota hai.

new Response(string, init)

Lower-level constructor. Agar aapko custom headers, custom statusText (jaise instructor ne "ProCodrr" set kiya), ya stream return karna ho, tab aap explicit new Response() use karte hain.

Next.js 15 Caching Change (Crucial Interview Topic!)

          
Did you know GET Route Handlers behave differently in Next.js 15?

        

      


      

        

           Major Shift in Next.js 15:
        

        

          In Next.js 14, a GET Route Handler with no dynamic parameters or headers was cached statically by default during build time.
          


          In Next.js 15, GET Route Handlers are UNCACHED by default (Dynamic)! Every call executes fresh on the server unless you explicitly configure:
          
export const dynamic = 'force-static';
        

      


      

        

          
            

              Next.js Version
              Default Caching for GET
              How to make it Dynamic
            

          
          
            

              Next.js 14
              Static (Cached at build time)
              Use Request object, cookies, or export const dynamic = 'force-dynamic'
            

            

              Next.js 15
              Dynamic (Uncached by default)
              Already dynamic! To cache, use export const dynamic = 'force-static'
