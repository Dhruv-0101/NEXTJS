Dynamic Route Handlers in Next.js

How to handle single-resource requests like /todos/1, parse dynamic route parameters with await params, and return standard 404 responses.

Folder Structure: app/todos/[id]/route.js

Creating parameterized endpoints in the Next.js App Router

Jab hume kisi specific todo ko fetch karna ho (jaise GET /todos/1), hum folder name square brackets [id] mein wrap karte hain.

Directory Architecture Route Mapping 
app/
└── todos/
    ├── route.js         ← Matches: /todos          (All todos)
    └── [id]/
        └── route.js     ← Matches: /todos/1, /todos/2 (Single todo)
app/todos/[id]/route.js Next.js 15 Implementation 
import todos from "../../../todos";

// In Next.js 15, params is an asynchronous Promise!
export async function GET(_, { params }) {
  // 🔴 MUST await params in Next.js 15!
  const { id } = await params;

  // Find matching todo (cast ID to string for safe comparison)
  const todo = todos.find((todo) => id === todo.id.toString());

  // If not found, return 404 with JSON error
  if (!todo) {
    return Response.json(
      { error: "Todo not found" },
      { status: 404 }
    );
  }

  return Response.json(todo);
}
Critical Next.js 15 Breaking Change: await params

In Next.js 14 and earlier, params was a synchronous object: const { id } = params;.
In Next.js 15, params is a Promise. Agar aap bina await ke access karenge, toh terminal mein warning aayegi aur production build fail ho sakta hai! Isliye function ko async banakar await params karna zaroori hai.
