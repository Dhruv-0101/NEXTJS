2. Server Component vs. Client Component Translation Hooks

⚙️ Server Component (Async)

Must use getTranslations from next-intl/server and await the result:

import { getTranslations } from "next-intl/server";

export default async function Home() {
  const t = await getTranslations("HomePage");
  return <h1>{t("title")}</h1>;
}
🌐 Client Component ("use client")

Must use useTranslations hook from next-intl (synchronous):

"use client";
import { useTranslations } from "next-intl";

export default function Home() {
  const t = useTranslations("HomePage");
  return <h1>{t("title")}</h1>;
}

6. Poora Saar & Golden Master Rule (Hinglish)

💡 Next.js Internationalization (i18n) Ka Poora Saar:

Next.js App Router me `next-intl` library se multi-language (English, Hindi, etc.) support setup karna bohot hi clean aur structured hai!

1. Dynamic Folder Architecture (`app/[locale]/`) 📂 ➔ Saare pages ko `app/[locale]/page.js` me rakhte hain. URL me `/en` ya `/hi` dynamically pass hota hai.
2. Middleware Detection (`middleware.js`) 🛡️ ➔ `createMiddleware(routing)` URL se locale detect karta hai aur bina-locale walle URLs ko default `/en` par redirect kar deta hai.
3. JSON Message Dictionaries (`messages/`) 📜 ➔ Har language ke liye alag JSON file hoti hai (`en.json`, `hi.json`).
4. Server vs Client Component Hooks ⚙️:
  • Server Components (Async) ➔ `const t = await getTranslations("HomePage");` (from `next-intl/server`).
  • Client Components (`"use client"`) ➔ `const t = useTranslations("HomePage");` (from `next-intl`).

🔥 i18n Golden Rules:
  • 1. Wrap pages in [locale] 📂 ➔ Place page routes inside `app/[locale]/` for dynamic URL language routing.
  • 2. Async getTranslations ⚙️ ➔ Always `await getTranslations()` inside async Server Components.
  • 3. Dynamic Import Dictionary 📜 ➔ Load messages dynamically in `i18n/request.js` via `import(\`../messages/\${locale}.json\`)`.
