2. Customizing Rules in `eslint.config.mjs`

import { FlatCompat } from "@eslint/eslintrc";

const compat = new FlatCompat({
  baseDirectory: import.meta.dirname,
});

const eslintConfig = [
  ...compat.config({
    extends: ["next/core-web-vitals", "next/typescript"],
    rules: {
      "@typescript-eslint/no-unused-vars": "warn", // 🟡 Downgrade error to warning
      "@next/next/no-img-element": "off", // 🟢 Allow standard <img> tags
      "@next/next/no-sync-scripts": "off",
    }
  }),
];

export default eslintConfig;

6. Poora Saar & Golden Master Rule (Hinglish)

💡 ESLint Setup in Existing Projects Ka Poora Saar:

Puraane existing Next.js codebase me ESLint setup karte waqt strict rules kabhi kabhi legacy code par hazaaron errors de dete hain!

1. Rule Customization (`rules: { ... }`) ⚙️ ➔ `eslint.config.mjs` me `rules` object ke andar specific strict rules ko `"warn"` (warning) ya `"off"` (disable) karke legacy project build ko fix kar sakte hain.
2. Example Rule Overrides 🛠️:
  • "@typescript-eslint/no-unused-vars": "warn" ➔ Unused variables par build crash hone ki jagah warning dikhayega.
  • "@next/next/no-img-element": "off" ➔ Standard HTML <img> tags par error aana band ho jayega.
3. Package Script 📜 ➔ `package.json` me `"lint": "next lint"` add karke terminal par single command se pooray codebase ki health check karo!

🔥 Existing Project Migration Golden Rules:
  • 1. Gradual Migration ⚙️ ➔ Downgrade strict rules to `"warn"` first so builds don't fail immediately.
  • 2. Use "off" Wisely 🛠️ ➔ Disable specific rules like `no-img-element` if legacy code heavily relies on HTML tags.
  • 3. Run next lint ⚡ ➔ Test migration using `npm run lint` before committing to Git repository.
