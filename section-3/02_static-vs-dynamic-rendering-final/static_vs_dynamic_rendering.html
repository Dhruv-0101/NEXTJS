Next.js Static vs Dynamic Rendering Master Guide

A comprehensive guide combining High-Level Architecture, Direct URL Visit Case Study (`/blogs/100`), Handwritten PDF Notes Analysis, and Line-by-Line Code Breakdown.

🧠 Hinglish Summary:
• Static Rendering: Production me code ek baar build time par chalta hai (`npm run build`). User visit par zero server calculation hoti hai, direct ready HTML serve hota hai!
• Dynamic Rendering: Production me jab user dynamic route (`/blogs/[blogID]`) pe jata hai, toh Next.js server har visit par JavaScript code ko re-render karta hai aur fresh UI return karta hai.

Special Question: What happens when a user directly visits `/blogs/100` in Production?

"Blog 1, 2, 3 ke link toh `/blogs` page par static HTML me the. Lekin agar koi user direct browser URL bar me /blogs/100 type kare ya direct request bhele, toh production me kya hoga?"

⚡ Answer: It triggers Live On-Demand Dynamic Rendering on the Server!

Isse farak nahi padta ki `/blogs` page par Blog 100 ka link tha ya nahi! Kyunki app/blogs/[blogID]/page.js ek Dynamic Route hai:

1️⃣ Browser direct request bhejega Node.js server ko: GET /blogs/100.
2️⃣ Next.js Node.js server live Blog({ params: { blogID: "100" } }) execute karega.
3️⃣ Server terminal me live print hoga: [SERVER LOG] blogID: 100.
4️⃣ Server instantly <h1>Welcome to Our Blog 100</h1> HTML generate karke browser ko send kar dega!
5️⃣ User ko screen par Blog 100 ka page mil jayega!

💡 Advanced Bonus: What if we used `generateStaticParams()`?

Agar humne generateStaticParams() se sirf blogID: 1 aur blogID: 2 pre-render kiye hote:
• Default Fallback (`dynamicParams = true`): User jab `/blogs/100` par pehli baar jata, tab Next.js server us response ko On-Demand Dynamic Render karta, aur target static HTML file ko cache kar leta future users ke liye!
• Strict Mode (`dynamicParams = false`): Next.js direct 404 Not Found page dikha deta.

1. Architectural Overview

Build Time Generation vs Request Time Rendering.

Static Rendering (Default)

Routes are rendered ONCE at build time. The resulting static HTML file is cached on a Content Delivery Network (CDN).

  • Execution Time: At next build phase.
  • Server Work per Visit: 0ms (Direct CDN static file response).
  • Server Logs: console.log() runs ONCE during build.
  • Performance: Maximum speed, minimal latency.
  • Best For: Marketing pages, Home page, About us, Blog posts.

Dynamic Rendering

Routes are rendered on the server for EVERY individual HTTP request. Ideal when user data, cookies, or real-time parameters change constantly.

  • Execution Time: Every time a user visits the URL.
  • Server Work per Visit: Full React component re-execution & rendering.
  • Server Logs: console.log() fires on EVERY user visit.
  • Performance: Dependent on database queries & server processing.
  • Best For: Personalized user dashboards, checkout carts, live search.

2. Analysis of `STATICVSDYNAMIC.pdf` Notes

Key points transcribed directly from handwritten course notes.

Handwritten Notes Core Points:

  • Build Execution: Production me static site ka code ek baar hi run hota hai jab hum build karte hain (`npm run build`).
  • Dynamic Request Execution: Jab hum dynamic page par jate hain, toh Next.js server JS code ko har visit par re-run karta hai aur dynamic rendering ke through pura UI dobara render hota hai.
  • Static Route Visit Behavior: Agar simple static page (`/about` ya `/foo`) pe jayen, toh **koi extra API/server request calculation nahi jati**, directly simple cached HTML mil jata hai.
  • Dynamic Navigation API Call: Agar dynamically UI se navigation karte hain (`/blogs/1`), toh fetch/API call dynamically params ke saath call hota hai, server par final HTML/RSC render hota hai, aur browser isko UI par dikhata hai.

3. Code Base Overview: Static vs Dynamic Route

Comparing app/blogs/page.js vs app/blogs/[blogID]/page.js

📄 Static Route: app/blogs/page.js

No dynamic route parameters or dynamic functions are used. Next.js automatically marks this route as Static.

import Link from "next/link"; const Blogs = () => { // 🟢 Fires ONCE during 'next build' in production! console.log("Blogs Page"); return ( <div> <h1>Welcome to Our Blog</h1> <Link href="/blogs/1">Blog 1</Link> </div> ); }; export default Blogs;

⚡ Dynamic Route: app/blogs/[blogID]/page.js

Uses dynamic route parameter params.blogID. Next.js automatically switches this route to Dynamic Rendering.

import Link from "next/link"; const Blog = async ({ params }) => { const { blogID } = await params; // 🔴 Fires ON EVERY USER REQUEST in production! console.log("blogID: ", blogID); return ( <div> <h1>Welcome to Our Blog {blogID}</h1> </div> ); }; export default Blog;

Deep-dive into every single line of code in static vs dynamic files.

Static File: app/blogs/page.js

Renders ONCE at `next build`
L1
import Link from "next/link";
Imports Next.js Client Router Link Component: Enables client-side soft navigation between pages without re-triggering full browser window reloads.
L3

Defines Component Function: Since 'use client' is not declared at the top, Next.js treats this as a React Server Component (RSC).

BUILD TIME EXECUTION Server Console Log:
• During npm run build, Next.js executes this function ONCE to pre-generate static HTML. You will see "Blogs Page" printed in build logs.
• In Production when users visit /blogs, Next.js serves pre-cached static HTML. Line 4 NEVER executes again on user visits!
L5-30
<nav>...</nav>
Static JSX Navigation Markup: Rendered into HTML markup at build time. Contains links for Home, About, Services, Blogs.
L31-44
<Link href="/blogs/1">...</Link>
Static Blog List Links: Generates static anchor links pointing to dynamic routes /blogs/1, /blogs/2, and /blogs/3.
L49
export default Blogs;
Default Export: Registers component as entry handler for /blogs route.

Dynamic File: app/blogs/[blogID]/page.js

Executes ON EVERY USER REQUEST
L1
import Link from "next/link";
Imports Link Component: Next.js link utility for client navigation.
L3
const Blog = async ({ params }) => {
Asynchronous Server Component: Receives props object containing params. The params object holds dynamic URL values matching folder name [blogID].
L4
const { blogID } = await params;
🔥 DYNAMIC TRIGGER LINE:
• Awaits dynamic route params promise to extract blogID (e.g. "1", "2", or "100").
• Because dynamic params cannot be predicted at build time for arbitrary IDs, this line forces Next.js to classify the route as Dynamic Rendering!
L5
console.log("blogID: ", blogID);
REQUEST TIME EXECUTION Live Terminal Server Log:
• Every time a user visits /blogs/1 or /blogs/100, Next.js executes Blog() on the Node.js server.
• Line 5 logs "blogID: 100" in real-time in your server console for EVERY SINGLE HTTP visit!
L6-36
<h1>Welcome to Our Blog {blogID}</h1>
Dynamic JSX Render: Injects dynamic blogID into rendered HTML header and returns freshly generated HTML payload to user browser.
L40
export default Blog;
Default Export: Registers component handler for dynamic parameter segment.
