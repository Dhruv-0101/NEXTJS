Streaming in Next.js with React Suspense

Learn how Next.js streams HTML chunks progressively over HTTP so slow data fetches (like a 15s comments call) never block the rest of the page from rendering instantly!

🧠 Hinglish Summary:
Purane SSR me jab tak poore page ka data fetch nahi hota tha (jaise Comments me 15s lage), tab tak user ko **safed khali screen (blank white page)** dikhti thi. Next.js **Streaming + React Suspense** me main layout aur header 0ms me turant dikh jata hai, aur jaise-jaise dynamic components tayar hote hain (Views 5s me, Likes 10s me, Comments 15s me), waise-waise HTML chunks browser par stream hokar UI ko replace kar dete hain!

Traditional SSR vs Streaming SSR

Comparing user experience & server blocking times.

❌ Traditional SSR (Without Streaming)

  • Server waits for ALL 3 components (Views 5s + Likes 10s + Comments 15s).
  • User sees BLANK screen for 15 full seconds!
  • Bad TTFB (Time to First Byte) & terrible UX.

🚀 Streaming SSR (Next.js + Suspense)

  • 0s: Navbar, Header & 3 Fallback Loading Spinners appear INSTANTLY!
  • 5s: `Views` chunk streams in ➔ Swaps spinner with "10k Views".
  • 10s: `Likes` chunk streams in ➔ Swaps spinner with "2k Likes".
  • 15s: `Comments` chunk streams in ➔ Swaps spinner with "500 Comments".

Project Codebase Overview

Examining app/blogs/page.js and component delays in project 07_streaming-in-next.js

📄 Main Page: app/blogs/page.js

import { Suspense } from "react"; import Views from "@/components/Views"; import Likes from "@/components/Likes"; import Comments from "@/components/Comments"; import Loading from "@/components/Loading"; const Blogs = () => { return ( <div> <h1>Welcome to Our Blog</h1> <Suspense fallback={<Loading>Views</Loading>}> <Views /> </Suspense> <Suspense fallback={<Loading>Likes</Loading>}> <Likes /> </Suspense> <Suspense fallback={<Loading>Comments</Loading>}> <Comments /> </Suspense> </div> ); };

⚙️ Async Components Delays:

// components/Views.js (5s Delay) export default async function Views() { await new Promise((res) => setTimeout(res, 5000)); return <div>10k Views</div>; } // components/Likes.js (10s Delay) export default async function Likes() { await new Promise((res) => setTimeout(res, 10000)); return <div>2k Likes</div>; } // components/Comments.js (15s Delay) export default async function Comments() { await new Promise((res) => setTimeout(res, 15000)); return <div>500 Comments</div>; }

Detailed analysis of app/blogs/page.js and component files.

File: app/blogs/page.js

React Suspense Boundary
L6
import { Suspense } from "react";
Imports React Suspense: The React API used to catch promises thrown by asynchronous components during server rendering and render a fallback UI until the component resolves.
L51-53
<Suspense fallback={<Loading>Views...</Loading>}>
5-SECOND STREAM BOUNDARY
• Wraps <Views />. While Views.js waits on its 5s setTimeout promise, Next.js streams the fallback <Loading>Views</Loading> component immediately.
• At 5s, the promise resolves and Next.js streams an HTML chunk replacing the fallback with 10k Views.
L54-56
<Suspense fallback={<Loading>Likes...</Loading>}>
10-SECOND STREAM BOUNDARY
• Wraps <Likes />. Fallback is rendered at 0s. At 10s, HTML chunk streams in to show 2k Likes.
L57-59
<Suspense fallback={<Loading>Comments...</Loading>}>
15-SECOND STREAM BOUNDARY
• Wraps <Comments />. Slowest data fetch on the page (15s). Streams in last without blocking Views or Likes!
